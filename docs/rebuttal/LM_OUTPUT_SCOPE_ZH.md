# AKR：LM 生成优化的研究目标与对照定位

更新日期：2026-11-10。

## 1. 研究目标

AKR 研究：利用少量带标签 support 拟合内部修正，在冻结 Speech LM 主干、query 不使用真实标签或反向传播的条件下，改善**由原 LM decoder 生成的答案**。这沿用 [论文摘要、引言和方法](../../paper/main.tex) 已有的问题定义。

主结果报告 LM 输出的 accuracy、macro-F1、invalid rate，以及相对 native 的 repaired/harmed；机制实验检验输入相关方向、注入位置、实际更新幅度与结果的关系。拟合与推理成本分别报告；稳定性须按实际完成的支持集和模型实验分别报告。

直接分类器的排名不作为这一研究目标的成败标准。实验叙事围绕 LM 生成路径的改善组织，实际对照结果按其角色如实呈现。

## 2. 训练、微调与推理状态修正的术语

| 方法 | 从 support 学习什么 | LM 主干权重 | 最终答案来源 | 准确称呼 |
|---|---|---|---|---|
| Native | 不拟合任务模块 | 冻结 | 原 LM decoder | 原生生成 |
| Audio ICL | 示例进入上下文，不更新参数 | 冻结 | 原 LM decoder | 上下文适配 |
| Direct ridge | 外部分类读出的权重与偏置 | 冻结 | 外部分类读出 | 冻结表示上的监督读出 / linear probe |
| Probe-to-LM | 外部读出；将其预测作为 prompt 证据 | 冻结 | 原 LM decoder | 外部证据条件下的 LM 生成 |
| 连续 AKR | 从声学特征到梯度修正坐标的映射 | 冻结 | 经 K/V 修正的原 LM decoder | 支持集拟合的推理状态修正 |
| Hard/soft 原型变体 | 类别路由读出与 support 梯度原型 | 冻结 | 经 K/V 修正的原 LM decoder | 类别原型路由的推理状态修正 |
| LoRA | LM 内部的可训练适配参数 | 原权重冻结，适配参数更新 | 带适配参数的 LM decoder | 参数高效微调 |
| 全参数微调 | LM 本身的权重 | 更新 | 微调后的 LM decoder | LM 参数微调 |

“拟合了任务模块”与“微调了 LM 参数”需要分开。Direct ridge 训练了外接读出，但没有改变 LM 主干；AKR 也拟合辅助映射或路由，因此 backbone frozen 不应被写成整个方法没有训练或监督。

## 3. 对照按研究问题组织

| 角色 | 实验 / 方法 | 回答的问题 |
|---|---|---|
| 原生生成参照 | C01 native；其他 case 的同条件 native | 修正后 LM 的答案是否改善，修复了多少、损害了多少？ |
| 支持条件下的 LM 生成对照 | C04 Audio ICL；C02 top-1 / distribution probe-to-LM | 相同支持标签下，不同信息输入方式如何改变 LM 的生成决策？ |
| 内部机制对照 | C05–C08 路由、幅度、固定/随机/打乱方向、K/V 与层位置 | 收益是否来自学习到的修正方向及其有效施加？ |
| LM 参数适配参考 | C13 matched-label LoRA | 使用相同标签预算更新适配参数时，LM 输出与成本如何变化？ |
| 外部读出诊断 | C02 direct ridge / probe-to-text；C03 声学特征读出 | 冻结表示经相同支持监督后能读出哪些任务信息？ |
| 专家 LM 参考 | C15 native NatureLM | 不同预训练背景与标签适用性下，专家 LM 生成表现如何？ |

LoRA 与冻结主干的 AKR 使用不同适配约束，应注明参数更新及计算成本。Probe-to-LM 与原型路由可共享类别读出信息，但 prompt 不含 K/V 梯度原型，不能声称二者获得完全相同的信息。

对于 hard/soft 原型版本，direct ridge 同时是**路由器自身输出的诊断**。代码先拟合 `RidgeReadout`，hard 用其 argmax 选择原型，soft 用分数转换出的权重加权原型。因此可报告 LM 输出与路由器决策的一致、纠正和损坏情况，同时保持 LM 生成改善为主要研究目标。相关实现见 [train50_methods.py](../../akr_final/train50_methods.py)。

Ridge 是实测的读出参考，不是理论上界、oracle，也不是 LM 主干微调。将类别标签渲染成文本仍然属于外部读出输出；`probe_to_text` 与 `ridge_direct` 不能计为两项独立强基线。

## 4. 对现有结果和方法身份的解释

- 连续 AKR、hard-centered 与 soft-cap 分别报告；原型变体的结果不能代替连续回归实现的验证。
- 主要收益以同一数据、支持预算、query 和输出评测规则下的 LM 生成对照判断。跨 case 的数值拼接不能自动获得逐样本配对检验的含义。
- C01 hard 与 soft 同时改变路由和幅度策略；C05 负责分离因素。方向控制的实际干预幅度必须有效且可比，不能用近乎零更新的控制证明强更新方向的优势。
- no-op、重复运行一致性、逐条预测证据和实际 BF16 更新仍是实现与机制证据的一部分。已有报告状态与后续代码修复分别陈述，代码修改本身不等于新的 GPU 验证结果。
- 研究对象是 LM 输出，不因此自动获得开放式问答、解释、多任务或长期能力保留的结论；这些能力需要对应实验。

> Our objective is to improve answers generated by an existing speech language model through support-fitted K/V corrections while keeping the backbone frozen. The main comparisons examine native generation, support-conditioned generation, and controlled state interventions under the declared supervision budget. We report direct ridge separately as an external readout diagnostic on frozen representations; it fits classifier parameters and does not fine-tune the LM backbone. For prototype-routed variants, this reference also characterizes the router decision before the corrected LM generates its answer. Matched-label LoRA provides a distinct model-parameter adaptation reference.
